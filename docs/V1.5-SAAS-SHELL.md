# CLASS TRACKER – V1.5 SaaS SHELL

This document defines the shell around the First Build Slice that turns ClassTracker into a paid, public, multi-teacher product. It sits between the First Build Slice (prove the loop works) and general release.

---

## 1. Purpose

The First Build Slice proves the product loop with one teacher, one class, and local data. V1.5 adds the minimum infrastructure required for:

- real teachers using it in real classrooms with real student data
- a publicly available, paid product
- safe, persistent, multi-teacher data storage

V1.5 does not add product features. It adds the shell that makes the slice sellable.

---

## 2. Scope

### In scope

- authentication
- cloud persistence
- per-teacher data isolation
- payment and subscription
- privacy and data handling
- onboarding flow
- basic account settings

### Out of scope (defer to later versions)

- school-level admin accounts
- multi-teacher shared classes
- full reporting module
- AI features
- long-term planning module
- pre/summary assessment module

---

## 3. Backend

**Choice: Supabase**

Reasons:

- Postgres under the hood, which fits the relational shape of the data (IC → Lesson → MasteryRecord)
- built-in auth including magic-link email
- Row Level Security enforces per-teacher data isolation cleanly at the database layer
- Sydney region (ap-southeast-2) available, satisfying Australian data residency
- generous free tier (500MB database, 50k MAUs) suitable for pilot and early paid use
- works with vanilla JS via a lightweight SDK — no build step, fits existing CLAUDE.md constraint

### Migration path

- First Build Slice may use local persistence or Apps Script for rapid iteration
- V1.5 migrates all persistence to Supabase before first paid users
- Schema designed from day 1 to be portable to Postgres

---

## 4. Authentication

**Primary: magic-link email**

A teacher enters their email, receives a link, clicks it, and is signed in. No password to remember or recover.

**Secondary: Google sign-in**

Offered as a "sign in faster" option for teachers who prefer it. Some school networks block personal Google accounts, so it cannot be the only option.

### Session rules

- sessions persist across browser restarts
- sign-out on explicit action only
- magic-link expires after 1 hour if unused

### No password-based auth in V1.5

Adds support burden (recovery flows, breaches, rules) with no matching benefit.

---

## 5. Data isolation

Every data row owned by a teacher must carry that teacher's user id. Supabase Row Level Security policies enforce:

- a teacher can only read rows they own
- a teacher can only write rows they own
- no cross-teacher data leakage under any query path

All entities defined in `DATA-SCHEMA-DOCUMENT.md` gain an implicit `ownerUserId` field at the V1.5 storage layer.

---

## 6. Hosting and data residency

- **Region:** Sydney (ap-southeast-2)
- **Reason:** Australian teachers, Australian students, Australian Privacy Principles
- **Backups:** daily automated snapshots retained for 30 days
- **Export:** teachers can export their data at any time (JSON or CSV)

---

## 7. Privacy and legal

Before first paid user, the product must have:

- a privacy policy covering what is stored, where, and for how long
- a terms of service
- a clear statement of data ownership: the teacher owns their data
- a data deletion process: account deletion removes all associated rows within 30 days
- Australian Privacy Principles compliance review

Student names are stored but are considered the teacher's data and are not shared, sold, or used for AI training.

---

## 8. Pricing

### Free tier

- 1 class
- up to 30 students
- all features
- time-limited to the **end of the current Australian semester**
- **if the teacher signs up with less than 3 weeks remaining in the current semester, free access continues to the end of the next semester**

Rationale: teachers plan by semester. A free tier that ends mid-semester is hostile to the planning workflow. A semester-aligned free tier lets a teacher try the product on a real cohort for a meaningful stretch.

### Paid tier

- unlimited classes
- unlimited students
- all features
- **~AU$8 / month** or **~AU$80 / year** (annual saves ~15%)

Exact pricing to be confirmed after pilot use.

### School plan

Deferred. Per-seat pricing with an admin dashboard, but not built until there is demonstrated school-level demand.

### Semester boundaries

The product must know current Australian semester dates. Source: a small lookup table, updated annually. Semester 1 runs late January to end of June. Semester 2 runs mid-July to mid-December. Exact end dates vary by state; use the earliest common end date to avoid ambiguity in free-tier expiry.

---

## 9. Payment

**Provider: Stripe**

- Stripe Checkout for initial subscription
- Stripe Customer Portal for self-service (cancel, update card, change plan)
- webhook-driven subscription state syncing to Supabase

### Failed payment behaviour

- 3 retries over 14 days
- account enters grace state: read-only access
- after 30 days with no payment: account flagged for archival, data retained for 90 days from that point

---

## 10. Onboarding

A first-time teacher must be able to, without help:

1. sign in via magic link
2. see a clear welcome screen explaining what the app does
3. create their first class in under 2 minutes
4. add students (paste from a list or add individually)
5. select subjects for the class
6. land on the Weekly Planner ready to create a lesson

No long setup wizard. No required profile fields beyond email and display name.

---

## 11. Account settings (minimum for V1.5)

- display name
- email
- current plan and billing
- data export (JSON + CSV)
- account deletion
- **reteach threshold slider** (default 40%, per `PRODUCT-RULES-DOCUMENT.md`)

---

## 12. Versioning and migration

- schema version stored alongside data
- migrations applied automatically on first load after release
- no destructive migration without export-first step

---

## 13. Success criteria for V1.5

V1.5 is ready for public paid use when:

- a new teacher can sign up, pay, and plan their first lesson in under 5 minutes
- no data loss has been observed across 4 consecutive weeks of pilot use
- account deletion completes cleanly and verifiably
- all data is in Sydney region
- privacy policy and terms of service are published and linked from the app

---

## 14. Explicit non-goals for V1.5

- school admin dashboards
- sharing classes between teachers
- parent-facing views
- student-facing logins
- real-time collaboration
- mobile app (the web app must work well on tablets and phones, but no native app)
- offline mode (will require separate design work later)

---

## Final principle

V1.5 is plumbing. It adds nothing teachers see as new product value. Its job is to make the slice safe, persistent, billable, and private. If a feature looks tempting to add here, it belongs in a later version.
